# 基于深度学习的共享单车流量预测调度系统

基于共享单车骑行记录，按小时聚合骑行流量，使用 LSTM 学习历史时序规律，预测下一时段的系统级骑行需求，为运力调度提供参考。

## 项目流程

1. 读取共享单车骑行数据，按骑行开始时间聚合为小时流量。
2. 提取骑行路线类别和会员类型特征，并进行 One-Hot 编码。
3. 使用 Min-Max 归一化构造时序特征矩阵。
4. 按时间顺序划分训练集、验证集和测试集，使用 14 步历史窗口预测下一时段流量。
5. 训练 LSTM 回归模型，并使用验证集损失保存最优模型。
6. 在测试集上进行反归一化预测，计算 RMSE、MAE 和 R²。

## 模型结构

- 输入：14 个历史时段、6 维特征
- LSTM：24 个隐藏单元
- 全连接层：48 个神经元
- 激活函数：LeakyReLU，`alpha=0.2`
- Dropout：`0.2`
- 输出：下一时段骑行流量
- 损失函数：均方误差（MSE）
- 优化器：RMSProp
- 训练配置：100 个 epoch，batch size 为 128

## 实验结果

Notebook 中记录的测试集结果如下：

| 指标 | 结果 |
| --- | ---: |
| RMSE | 14.6554 |
| MAE | 10.9287 |
| R² | 0.7159 |

目标变量是按小时统计的骑行次数，因此 RMSE 和 MAE 的数值单位对应“次/小时”。结果表明，模型能够解释约 71.6% 的测试集流量波动，平均绝对误差约为 11 次/小时，可为系统级骑行需求预估和运力调度提供参考。

## 运行环境

建议使用 Python 3.8+，安装以下依赖：

```bash
pip install pandas numpy matplotlib scikit-learn tensorflow xlrd
```

其中 `xlrd` 用于读取 `.xls` 数据文件。

## 运行方式

1. 将 `代码.ipynb`、`共享单车数据十万条1.xls` 和本 README 放在同一目录。
2. 启动 Jupyter Notebook 或 JupyterLab。
3. 按顺序运行 notebook 单元格。
4. 训练完成后，使用保存的 `lstm_model.h5` 在测试集上评估模型。

## 实现边界

- 当前预测目标是全局小时骑行流量，不是具体站点的借车量或还车量。
- 当前 notebook 未实现车辆库存约束、站点间调度路径和调度优化算法。
- 数据按实际出现记录的小时聚合，未额外补齐没有骑行记录的小时；用于生产部署前应进一步处理完整时间轴、天气、节假日和站点库存等信息。
